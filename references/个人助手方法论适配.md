## 六、15 轮自动 profile 实现规范

### 6.1 "轮"的计数口径

- 一轮 = 一次用户输入 + 一次助手完整响应（含该响应内的全部工具调用）。
- 助手响应内的多次工具调用**不**各自计轮，合并计入同一轮。
- 系统注入消息（如上下文刷新、技能加载提示）**不**计轮。
- 计数器 `turn_count` 在每轮助手响应结束时 +1，持久化于会话状态。

### 6.2 触发条件

满足任一即触发 profile 生成：

- `turn_count >= 15`（硬阈值）。
- 或上下文 token 占用 > 70%（软阈值，防溢出优先于轮数）。
- 触发后**不重置**计数；改为"每 +8 轮再生成一次增量 profile"（即 15、23、31……），避免长会话反复全量压缩。

### 6.3 profile 内容结构

profile 是对话的**压缩摘要**，不是事由台账的副本。结构固定：

```
[PROFILE @ turn=N]
当前任务：起草/改写/审查 + 通知类型（7 种之一）+ 语气档位
事由台账快照：发文机关/主送/事由/依据/行政目的/读者关切/附件情况（已确认项+〔待补〕项）
关键决策日志：通知类型选择、语气档位、结语选择、附件标注方式（每条一行）
已交付物：已输出的净稿/附注/评分，及其版本号
未决阻塞：仍待用户确认的事项清单
活跃引用：本轮正在使用的 references/assets 文件路径
[END PROFILE]
```

### 6.4 生成方式

- **静默生成，不打断用户**：profile 写入会话状态/内存，不向用户输出长文本。
- 仅当 profile 过程中发现"关键假设从未被用户确认"时，才用一次 grill-me 提示确认（受"同会话最多 2 次 grill 提示"约束）。
- 生成耗时不应阻塞当前轮的工具结果呈现。

### 6.5 释放策略

profile 生成后，按以下顺序释放上下文：

1. 释放：早期轮次的逐字对话、已读取但当前未引用的 references 全文、工具原始大输出（如抓取的 HTML 全文）。
2. 保留：profile 本身、事由台账结构化数据、最近 2 轮的完整对话、SKILL.md 路由骨架、当前活跃引用文件。
3. 保留锚点：所有〔待补〕〔待确认〕标记及其上下文，不得在压缩中丢失。

### 6.6 恢复机制

profile 之后继续工作时：

- 助手先以 profile 为"工作记忆"恢复任务状态，**不**重读已释放的 references 全文，除非当前步骤确需（按需重新加载，走资料导航路由）。
- 若用户的新输入与 profile 记录的"当前任务/通知类型"冲突，视为**任务切换**，触发 6.8 边界处理。
- 恢复后的首轮响应，助手内部核对 profile 与用户新输入的一致性，不一致时先澄清再继续。

### 6.7 与事由台账的关系

- 事由台账 = **结构化业务数据**（字段化、可校验、零编造的硬约束载体），全程保留，不被 profile 替代。
- profile = **对话过程摘要**（决策脉络、已交付物、阻塞项），用于压缩上下文。
- 二者互补：profile 回答"我们聊到哪了、决定了什么"，台账回答"这份通知的事实要素是什么"。压缩时台账以快照形式嵌入 profile，但台账本体不删。

### 6.8 边界情况

| 情况 | 处理 |
|---|---|
| 用户中途切换通知类型 | 旧通知台账归档进 profile 的"已交付/已搁置"区，新建台账，turn_count 不重置 |
| 长会话跨多个通知 | 每个通知独立台账；profile 维护"通知清单+当前活跃通知指针" |
| 用户在 profile 后纠正早期决策 | 更新决策日志并标注"覆盖 turn=X 的决定"，不删除历史日志 |
| 上下文已溢出但未满 15 轮 | 软阈值触发，立即生成 profile 并释放，不等轮数 |
| 会话结束/用户说"退出" | 将最终 profile + 最终台账落盘为会话摘要文件（本技能全🟢可直接存本地） |

